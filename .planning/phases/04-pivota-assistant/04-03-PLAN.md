Purpose: This is where the five named demo questions actually resolve, where every factual claim gets a persisted citation, and where the hard line between a Decline (model text) and an error (503 channel) is drawn — the three visually-unambiguous outcomes depend on this backend separation.

Output: `src/services/assistant.ts`, `POST /api/assistant/chat`, `GET /api/assistant/conversations/:id`, and integration tests proving the 5 questions resolve, zero-ungrounded, sealed→decline, 503-on-missing-key, and error-never-rendered-as-decline.

```typescript
import type { MessageRole } from '@prisma/client';

export interface CitationInput {
  recordType: 'ExhibitEvent' | 'DiscrepancyFlag' | 'JuryPackageExhibit';
  recordId: string;
  exhibitId: string;        // ADDITIVE (04-01 columns): pill deep-link target exhibit
  eventId: string | null;   // ADDITIVE: timeline anchor; null for types with no single event
  timestamp: string; // ISO
  label: string;
}

// TechArch 03-api.md §4.10 + the additive exhibitId/eventId link fields (04-01).
// These two fields make the pill link a FIRST-CLASS part of the citation so replayed
// citations (GET /conversations/:id) link exactly as fresh-stream ones do.
export interface Citation {
  recordType: 'ExhibitEvent' | 'DiscrepancyFlag' | 'JuryPackageExhibit';
  recordId: string;
  exhibitId: string;
  eventId: string | null;
  timestamp: string;
  label: string;
}
export interface ConversationDetail {
  conversation: { id: string; caseId: string; userId: string; startedAt: string };
  messages: Array<{ id: string; role: 'USER' | 'ASSISTANT'; content: string; createdAt: string; citations: Citation[] }>;
}
```

Functions:
1. `createConversation(caseId: string, userId: string): Promise<AssistantConversation>` — a plain insert. (Called by the chat route on FIRST message when no conversationId is supplied — CONTEXT.md: no empty orphan conversations.)

3. `getConversationDetail(id: string): Promise<ConversationDetail>` — load the conversation with `messages: { orderBy: { createdAt: 'asc' }, include: { citations: true } }`; throw `new NotFoundError('CONVERSATION_NOT_FOUND', 'No conversation found with the given ID')` if the conversation does not exist (Y2-errors.md). Map to the `ConversationDetail` shape with ISO strings — **including `exhibitId` and `eventId` on every returned citation** so a replayed thread's pills deep-link exactly like fresh-stream ones.

Keep this a pure service (no Next types). JSDoc the single-writer discipline and the zero-citation-only-if-decline invariant.

**⚠️ THIS ROUTE IS THE SINGLE SOURCE OF TRUTH FOR THE CLIENT↔SERVER WIRE CONTRACT.** 04-04 (hook) and 04-05 (UI + E2E mock) are BOUND to the contract this task implements and records in 04-03's SUMMARY — the request envelope (useChat message array + caseId/userId/conversationId/role tagging), how conversationId is returned (header vs stream data), and how citations (incl. the exhibitId/eventId link fields) are carried in the stream's custom-data/annotations. Flow:
1. **Parse the request.** Body is `AssistantChatRequest { caseId: string; userId: string; message: string; conversationId?: string }` — but the client uses `useChat`, which POSTs its own `{ messages }` envelope. Accept the useChat message array AND the tagging fields (caseId/userId/conversationId/role threaded via useChat `body`/headers — 04-04 wires the client side; here, read role from `parseRequestingRole(request)` as every other route does, and read caseId/userId/conversationId from the request body or custom headers). Derive the latest user `message` text from the useChat payload. Document the exact contract you implement so 04-04 matches it.
2. **503 guard FIRST (criterion 5):** if `!isAssistantConfigured()`, return `errorResponse(new AssistantUnavailableError())` → 503 BEFORE any LLM call or DB write. This is the ONLY place the missing-key path is decided; the app itself already boots fine (04-01).
3. **Conversation:** if `conversationId` is absent, `await createConversation(caseId, userId)` NOW (first message creates it — CONTEXT.md). Capture the id to return to the client (via a response header or the stream's final payload) so the client can hold it in zustand.
4. **streamText:** call `streamText({ model: anthropic(ANTHROPIC_MODEL), temperature: ASSISTANT_TEMPERATURE, system: buildSystemPrompt(role), tools: buildAssistantToolSet({ caseId, requestingUserRole: role }), messages: <converted useChat messages>, ... })`. Import the provider: `import { anthropic } from '@ai-sdk/anthropic'` (it reads ANTHROPIC_API_KEY from env — but we've already gated on isAssistantConfigured). Allow multi-step tool-calling (set the version's `maxSteps`/`stopWhen` so the model can call a tool then compose the answer). Pass `temperature: 0` and the pinned model id — determinism is a release blocker.
5. **Error-vs-decline separation (criterion 5 — CORRECTNESS CRITICAL):** wrap the streamText setup so that a provider/transport error (unreachable, timeout, auth) does NOT become streamed assistant text. Use the SDK's `onError` and/or wrap the initial call in try/catch: on a provider failure, return/emit the 503 ASSISTANT_UNAVAILABLE on the ERROR channel (an HTTP 503 if the failure happens before streaming starts; if mid-stream, surface it via the stream's error event, NOT as a text token). Set a request timeout (Claude's Discretion for the threshold — e.g. abort after ~20s) that trips ASSISTANT_UNAVAILABLE. A Decline must ONLY ever be the model's own grounded-fallback TEXT; the route must never synthesize "I don't have that information" on an error.
6. **Citation extraction + persistence (criterion 2) — MUST cover ALL citation-producing tools.** In the SDK's `onFinish` callback, walk the tool calls + results produced THIS turn and derive a `CitationInput[]`. Every citation carries `{ recordType, recordId, exhibitId, eventId, timestamp, label }`. The route knows each tool call's `exhibitId` argument and each result row's source event id, so it populates the link fields per record type. **A grounded answer from ANY of these tools MUST yield ≥1 citation — otherwise the model's grounded sentence has no pill (fails zero-ungrounded, criteria 1/2) AND 04-04 would mis-classify the turn as a Decline (it keys decline off zero citations).** Map EACH tool (not just three):

   - **getExhibitStatus** → `ExhibitCurrentState` → ONE `ExhibitEvent` citation: `recordId` = `lastStatusEventId`, `exhibitId` = the arg exhibitId, `eventId` = `lastStatusEventId`, `timestamp` = `lastStatusAt`, label e.g. "Status: ADMITTED · Oct 6, 2026".
   - **getCustodian** → `CustodyCurrentState` → ONE `ExhibitEvent` citation: `recordId`/`eventId` = `lastEventId`, `exhibitId` = arg exhibitId, `timestamp` = `since`.
   - **getCustodyHistory** → each inline entry `{ …, eventId }` → ONE `ExhibitEvent` citation PER entry: `recordId`/`eventId` = entry `eventId`, `exhibitId` = arg exhibitId, `timestamp` = entry `timestamp`.
   - **getExhibitHistory** → each cited `timeline[]` entry → ONE `ExhibitEvent` citation: `recordId`/`eventId` = entry `eventId`, `exhibitId` = arg exhibitId, `timestamp` = `recordedAt`.
   - **getUnresolvedObjections** → each returned `ObjectionCurrentState` row → ONE `ExhibitEvent` citation PER listed objection (CONTEXT.md "one pill per listed item"): `recordId`/`eventId` = row `raisedEventId`, `exhibitId` = row `exhibitId`, `timestamp` = `raisedAt`.
   - **getDiscrepancies** → each returned `DiscrepancyFlag` → ONE `DiscrepancyFlag` citation PER flag: `recordId` = flag `id`, `exhibitId` = flag `exhibitId`, `eventId` = `null` (a flag has no single timeline event — the pill lands at top-of-timeline; if the flag exposes a detectedAt-source event id, use it instead), `timestamp` = `detectedAt`.
   - **getJuryPackageStatus** → each returned `JuryPackageExhibit` row → ONE `JuryPackageExhibit` citation PER row: `recordId` = row `id`, `exhibitId` = row `exhibitId`, `eventId` = `null`, `timestamp` = `addedAt`.
   - **searchExhibits** → each returned `ExhibitListRow`. A search row has an `exhibitId` but NO event id. **DECISION (pick the PREFERRED path): widen the `searchExhibits` tool's returned shape for the assistant so each row includes its current-status event id** — i.e. have the tool attach `currentStatus.lastStatusEventId` to each row (sourced from the same role-filtered read) so the assistant can cite the status event. Emit ONE `ExhibitEvent` citation PER row: `recordId`/`eventId` = row `lastStatusEventId`, `exhibitId` = row `exhibitId`, `timestamp` = row `lastStatusAt`, label e.g. "Exhibit 7 · ADMITTED". (If widening the tool shape proves infeasible at execution, FALL BACK to a per-row citation with `recordType: 'ExhibitEvent'` is NOT valid without an event id — instead cite the exhibit with `eventId: null` and `recordId` = a REAL record id for that exhibit's latest event, landing at top-of-timeline; document whichever path was taken in the SUMMARY.) Either way, **"what exhibits were admitted yesterday" MUST NOT produce an uncited grounded answer** — one pill per listed exhibit.

   NOTE — widening searchExhibits touches 04-02's tool shape: the preferred path adds `lastStatusEventId`/`lastStatusAt` to the assistant-facing search row. If the executor takes it, make the matching change in `src/lib/assistant/tools.ts` (searchExhibits tool) and extend `tools.test.ts` to assert the row carries the status event id — keep the service's own `searchExhibits` return untouched (map/augment inside the tool, preserving 1:1 data provenance from the same role-filtered read).

Then `await persistTurn({ conversationId, userMessage, assistantContent, citations })`. Also send the citations (with exhibitId/eventId) + conversationId to the client in the stream's final structured payload (so the UI renders pills without a second fetch) — use the custom-data/annotations mechanism pinned in 04-01's SUMMARY. If the model Declined (no supporting tool records), citations is `[]` — persist the message with zero citations (valid Decline).
7. Return the SDK's streaming Response (`toUIMessageStreamResponse()` or equivalent), including the conversationId header so the client can capture a freshly-created conversation.
