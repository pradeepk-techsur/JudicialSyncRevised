<objective>
Fix the UAT-confirmed citation-gating bug (04-UAT.md test 7, major, proven): `onFinish` in `src/app/api/assistant/chat/route.ts` currently calls `extractCitations(steps)` unconditionally — deriving a citation for every row ANY tool returned this turn — with zero awareness of whether the model's own final `text` is actually a Decline. When the model calls a tool (e.g. `searchExhibits`) but then declines in its final text because the returned rows don't actually answer the literal question asked (the live-reproduced case: "what exhibits were admitted yesterday" returns all ADMITTED exhibits with no date filter, so the model correctly declines on the date criterion while the tool still returned 5 rows), the route still emits 5 citations alongside decline text. Because 04-04's client-side outcome classifier keys `grounded` vs `decline` PURELY on `citations.length`, this turn renders with citation pills despite the model's own words being an unambiguous decline — contradicting the three-unambiguous-outcomes guarantee.

This plan adds a minimal, surgical gate: before persisting/streaming citations, check whether `text` matches the system prompt's own required decline phrasing ("I don't have that information" — already asserted against in the existing test suite at lines 217/246/255 of route.test.ts, and specified verbatim in FRD §F07 line 8/41/67/69). If it does, force `citations = []` regardless of what `extractCitations` derived. If it does not, use `extractCitations(steps)` exactly as before — preserving the ≥1-citation-for-a-grounded-answer guarantee untouched.

Purpose: Close the single open UAT gap (test 7, major severity, proven) without touching GATE.md (0 open) or SECURITY.md (SECURED, 0 confirmed HIGH/CRITICAL) territory — this is a pure correctness fix confined to one file already owned by 04-03.

Output: An updated `onFinish` handler in `src/app/api/assistant/chat/route.ts` with a new `isDeclineText()` guard, plus route.test.ts coverage proving both (a) the exact reproduction case now yields `citations: []`, and (b) a genuinely grounded answer on the identical tool path still yields its citations.
</objective>

```typescript
/** The system prompt's required decline phrasing (systemPrompt.ts: "respond with
 *  a brief, plain decline of the form 'I don't have that information'"; FRD §F07
 *  line 8/41/67/69 — "I don't have that information" or an equivalent explicit
 *  statement). A case-insensitive substring match against this exact phrase is
 *  the same signal the existing test suite already asserts on (route.test.ts
 *  lines 217/246/255), so this gate is consistent with what the prompt already
 *  enforces and what tests already assume — no new behavior invented.
 *
 *  CRITICAL (criterion 2 / 04-UAT.md test 7): a tool call returning rows THIS
 *  TURN does not make the answer grounded — only the model's own final text
 *  deciding to state a fact grounded in those rows does. When the model's text
 *  is a Decline (because, e.g., the returned rows don't actually answer the
 *  literal question — no date-filter support in searchExhibits is the proven
 *  repro), citations MUST be forced to [] even though extractCitations(steps)
 *  would otherwise derive one per returned row. This keeps the wire contract's
 *  "a Decline carries citations: []" promise (04-03 SUMMARY) true in EVERY
 *  case, not just the no-tool-call case, which is what 04-04's purely
 *  citations.length-keyed outcome classifier depends on. */
export function isDeclineText(text: string): boolean {
  return text.toLowerCase().includes("i don't have that information");
}
```

Then in the `onFinish` callback (around line 160-188), change:

```typescript
onFinish: async ({ text, steps }) => {
  const citations = extractCitations(steps);
  ...
```

to:

```typescript
onFinish: async ({ text, steps }) => {
  // Gate citation extraction on the model's own final text (criterion 2 /
  // 04-UAT.md test 7 fix): a tool returning rows this turn is NOT sufficient
  // for "grounded" — only the model's text actually asserting a fact grounded
  // in those rows is. A textual Decline ALWAYS persists/streams citations: [],
  // regardless of what extractCitations(steps) would otherwise derive, so the
  // client's citations.length-keyed outcome classifier (04-04) never shows
  // pills on a declining answer.
  const citations = isDeclineText(text) ? [] : extractCitations(steps);
  ...
```

Do NOT touch anything else in the file: `extractCitations`, `citationsForToolResult`, the 503 guard, the error/transport handling (`onError`, `isLikelyProviderError`), `persistTurn`, or the `writer.write({ type: 'data-citations', ... })` call. The gate is a single conditional at the point citations are computed — everything downstream (persistence, the stream data part) already treats an empty array as a valid Decline (04-03 established this invariant; this plan makes the computation of that array correct for the case where a tool fired but the model still declined).

Keep `isDeclineText` exported (module-level, alongside the existing `extractCitations`/`citationsForToolResult` which are also at module scope) so route.test.ts can unit-test the phrase-matching logic directly, mirroring the existing `toDiscrepancyFlagDto` export precedent in `src/app/api/cases/[id]/discrepancies/route.ts`.
