Implement `export async function getRecentActivity(caseId: string, opts: { since?: string; role: Role }): Promise<RecentActivityEntry[]>`:

1. **Validate `since` if supplied** (FRD F08 §Validation): parse with `new Date(since)`; if `Number.isNaN(d.getTime())` OR `d.getTime() > Date.now()` → `throw new ValidationError('since must be a valid past or present datetime')` (422; import ValidationError from '@/lib/errors'). A supplied-but-valid `since` becomes the window start.

2. **Default window = start of the day of the LATEST ledger event in the case** (CONTEXT locked decision — a rolling "latest trial day" so the demo is never empty regardless of run date). When `since` is NOT supplied:
   - Query the most recent event's `recordedAt` for this case: `prisma.exhibitEvent.findFirst({ where: { caseId }, orderBy: { recordedAt: 'desc' }, select: { recordedAt: true } })`.
   - If none exists (empty case) → return `[]` (no window to anchor; the UI shows the calm empty state).
   - Otherwise set `windowStart` = start-of-day (local server time; `d.setHours(0,0,0,0)` on a copy) of that latest `recordedAt`. This is a rolling anchor, NOT wall-clock today.

3. **Query the ledger, newest-first, role-scoped sealed exclusion as a WHERE predicate** (never a post-filter — mirrors exhibits.ts / history.ts; CONTEXT: "sealed events never leak"). Join the exhibit for its label AND to apply the sealed predicate, and join the actor for custody-name resolution:

```ts
const events = await prisma.exhibitEvent.findMany({
  where: {
    caseId,
    recordedAt: { gte: windowStart },
    // Same sealed-exclusion predicate as every other read: a sealed exhibit's
    // events are simply ABSENT for a role that cannot view sealed — never a
    // redacted row, never counted. Uses the exhibit relation's isSealed.
    ...(canViewSealed(opts.role) ? {} : { exhibit: { isSealed: false } }),
  },
  orderBy: { recordedAt: 'desc' },   // newest-first (FRD §Process step 2)
  include: {
    exhibit: { select: { id: true, exhibitLabel: true } },
  },
});
```
Import `canViewSealed` from '@/services/visibility'. The `@@index([caseId, eventType, recordedAt])` on ExhibitEvent (schema.prisma) backs this query — no new index needed. NO hard row cap (CONTEXT: "scroll, don't truncate/paginate").

Implementation:

```ts
import { NextResponse, type NextRequest } from 'next/server';
import { getRecentActivity } from '@/services/activity';
import { parseRequestingRole } from '@/services/visibility';
import { errorResponse } from '@/lib/apiError';
import { AppError, CommandCenterLoadError } from '@/lib/errors';

export async function GET(
  request: NextRequest,
  context: { params: Promise<{ id: string }> },
): Promise<NextResponse> {
  try {
    const { id: caseId } = await context.params;
    const requestingUserRole = parseRequestingRole(request);
    const since = request.nextUrl.searchParams.get('since') ?? undefined;
    const activity = await getRecentActivity(caseId, { since, role: requestingUserRole });
    return NextResponse.json(activity, { status: 200 });
  } catch (err) {
    // A client-input problem (bad/future `since`) is a typed ValidationError
    // (422) and must pass through unchanged. Anything else — an unexpected DB/
    // service failure — becomes COMMAND_CENTER_LOAD_FAILED (500) per FRD F08
    // §Error States, so the panel can show "Unable to load trial activity —
    // please retry" rather than a bare 500.
    if (err instanceof AppError) {
      return errorResponse(err);
    }
    return errorResponse(new CommandCenterLoadError());
  }
}
```

Rationale for the catch shape: getRecentActivity throws a typed `ValidationError` (AppError subclass) for a bad `since` — that keeps its 422 via errorResponse. Any non-AppError (a genuine query failure) is wrapped as CommandCenterLoadError so the FRD's 500 code + message is what the client sees. Do NOT catch-and-swallow; always return a response.
