<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API (jury screen actions) | initiate/finalize/acknowledge requests carry actorUserId + justification from the browser into privileged routes |
| db→render (finalized export) | finalized exhibit list (role-filtered) rendered and printed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Elevation of privilege | client-side finalize/acknowledge gating | mitigate | The UI hides finalize/acknowledge controls for view-only roles, but the AUTHORITATIVE gate is the server route (03-02 finalizeJuryPackage / acknowledgeDiscrepancy role checks returning 403); the client never authorizes — it only renders. Residual client-trust is backstopped server-side. |
| T-03-13 | Spoofing | stale-client finalize | mitigate | useJuryPackage.finalize surfaces the server's fresh-gate 409 (JURY_PACKAGE_DISCREPANCIES_OPEN) and refetches; the client cannot finalize a package the server currently blocks — the disabled attribute is a convenience, the server is the gate (relies on 03-02 T-03-07). |
| T-03-14 | Information disclosure | sealed exhibit in export/print | mitigate | The finalized list + print render only the server-provided exhibits, which getJuryPackage already role-filters (03-02 T-03-06); window.print() prints the role-filtered DOM, so a role without sealed visibility never prints a sealed exhibit. |
| T-03-15 | Tampering (XSS) | justification / labels rendered in banners | accept | Justification free-text and rule labels are rendered via React auto-escaping only (no dangerouslySetInnerHTML); residual risk is React's default escaping which owns safe rendering (consistent with T-01-21). Owner: frontend. |
</threat_model>
