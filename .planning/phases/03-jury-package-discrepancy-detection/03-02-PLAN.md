Create `src/services/juryPackage.ts`. Follow the established service style (typed errors, projection reads, recordEvent as sole ledger writer where a ledger write is needed). Role authorization for writes resolves actorUserId's actual User.role; sealed-visibility for reads uses the passed requestingUserRole + canViewSealed (import from @/services/visibility). Export:

Define a `JuryPackageExhibitView` interface matching TechArch 03-api.md EXACTLY:
```typescript
interface JuryPackageExhibitView {
  exhibitId: string;
  exhibitLabel: string;
  currentStatus: ExhibitStatus;   // ADMITTED for all rows
  discrepancyStatus: 'CLEAN' | 'FLAGGED';  // LIVE, freshly evaluated
  addedAt: string;
}
```

1. `computeJuryCandidates(caseId: string, requestingUserRole: Role): Promise<{ exhibitId: string; exhibitLabel: string; currentStatus: 'ADMITTED' }[]>`
   - Read ExhibitCurrentState WHERE currentStatus = 'ADMITTED' joined to exhibits of this case.
   - Apply sealed exclusion via `canViewSealed(requestingUserRole) ? {} : { isSealed: false }` in the WHERE (sealed-invisibility must hold here too — a role without sealed visibility never sees a sealed admitted exhibit in the candidate list). Order by exhibitLabel asc.

2. `initiateJuryPackage(caseId: string, actorUserId: string): Promise<{ juryPackage: JuryPackage; exhibits: JuryPackageExhibitView[] }>` — the EXPLICIT initiate (POST). 
   - Role gate: actorUserId's role must be DEPUTY/CLERK/ADMIN else RoleNotPermittedError (403).
   - One-living-DRAFT, idempotent: if a DRAFT JuryPackage already exists for the case, do NOT create a second — reconcile it (see getJuryPackage reconcile logic) and return it. If the most recent package is FINALIZED, create a NEW DRAFT from current candidates.
   - Candidates = computeJuryCandidates(caseId, 'ADMIN') (initiate is role-gated to full-visibility roles, so use a sealed-visible role for candidate computation — the acting deputy/clerk/admin all can see sealed per SEALED_VISIBLE_ROLES? NOTE: DEPUTY/CLERK are NOT in SEALED_VISIBLE_ROLES. Use the actor's OWN resolved role for computeJuryCandidates so a DEPUTY-initiated package excludes sealed exhibits consistently with what that deputy sees on screen).
   - If zero candidates → throw `new UnprocessableError('NO_ELIGIBLE_EXHIBITS', 'No admitted exhibits are eligible for a jury package')` (422).
   - Create the JuryPackage (status DRAFT) and its JuryPackageExhibit rows (discrepancyStatus = live CLEAN/FLAGGED per exhibit — see mapping below) in one transaction. Return the view.

3. `getJuryPackage(caseId: string, requestingUserRole: Role): Promise<{ juryPackage: JuryPackage | null; exhibits: JuryPackageExhibitView[] }>` — READ-ONLY (ROADMAP criterion 5 + F11). MUST NOT create a package as a side effect.
   - Find the most recent JuryPackage for the case (order createdAt desc).
   - If NONE → return `{ juryPackage: null, exhibits: [] }` (the "no package started yet" state). Create nothing.
   - If FINALIZED → return it read-only with its stored JuryPackageExhibit rows mapped to the view (finalized snapshot; still filter sealed exhibits the requesting role can't see from the returned list).
   - If DRAFT → RECONCILE to the live ADMITTED candidate set (CONTEXT "Auto-reconcile"): compute current candidates (scoped to requestingUserRole for sealed-visibility), add JuryPackageExhibit rows for newly-admitted exhibits, remove rows for exhibits no longer ADMITTED. This reconcile MAY write (add/remove rows + refresh the stored discrepancyStatus hint) — that is a legitimate reconcile, distinct from "creating a draft on view". The prohibition is specifically on CREATING a package when none exists; reconciling an EXISTING draft is explicitly allowed by CONTEXT. Then return the live view.

   Live discrepancy mapping (used by all three above): for each included/candidate exhibit, compute its LIVE discrepancy status — `getExhibitDiscrepancies(exhibitId)` returns OPEN+ACKNOWLEDGED flags; map to `FLAGGED` if any flag exists (OPEN or ACKNOWLEDGED), else `CLEAN`. The stored `discrepancy_status` column is refreshed to this value on reconcile so it never silently diverges, but the VIEW always reflects the fresh computation. (Note: for the finalize GATE, "FLAGGED" is not enough detail — the gate specifically checks for OPEN flags; see Task finalize below.)

4. `finalizeJuryPackage(juryPackageId: string, actorUserId: string, acknowledgedDiscrepancyIds?: string[]): Promise<{ juryPackage: JuryPackage }>` — hard gate, re-evaluated FRESH.
   - Load the package; if missing → NotFoundError('JURY_PACKAGE_NOT_FOUND', ...) 404.
   - If already FINALIZED → throw `new ConflictError('JURY_PACKAGE_ALREADY_FINALIZED', 'This jury package has already been finalized')` 409.
   - Role gate: actorUserId role must be DEPUTY/CLERK/ADMIN else RoleNotPermittedError 403.
   - FRESH re-evaluation: for EVERY included JuryPackageExhibit, call `evaluateDiscrepancies(exhibitId)` (no tx — fresh standalone eval, OR inside the finalize transaction for atomicity; prefer inside the transaction) so flags reflect current state, then read each exhibit's flags. An exhibit BLOCKS iff it has ≥1 flag with status OPEN. ACKNOWLEDGED and RESOLVED do NOT block. NEVER trust the cached JuryPackageExhibit.discrepancyStatus column for the gate.
   - If any blocking exhibits → throw a ConflictError with code `JURY_PACKAGE_DISCREPANCIES_OPEN`, message `Cannot finalize: ${n} exhibit(s) have unresolved discrepancies`, AND attach the blocking exhibit list to the error so the route can include it in the response body. Add an optional `details` field to ConflictError (or create a dedicated error subclass carrying `blockingExhibits: {exhibitId, exhibitLabel, ruleCodes: string[]}[]`) — the 409 body MUST name the blocking exhibit(s) (ROADMAP criterion 3). Extend src/lib/errors.ts minimally if needed (e.g. an optional `details?: unknown` on AppError surfaced by errorResponse).
   - If clean → update JuryPackage to status FINALIZED, finalizedAt now, finalizedBy actorUserId. Return it.

Error-envelope note: if you add `details` to AppError, update src/lib/apiError.ts's errorResponse to include `details` in the envelope when present: `{ error: { code, message, details? } }`. Keep backward-compatible (omit when undefined).

Create `src/services/juryPackage.test.ts` (vitest integration). Use a self-contained fixture case (unique caseNumber) or the seeded case; follow history.test.ts / discrepancies.test.ts conventions (fileParallelism:false). Cover:

  - initiateJuryPackage by DEPUTY creates a DRAFT with the admitted set; a second initiate returns the SAME DRAFT (no duplicate); by ATTORNEY → ROLE_NOT_PERMITTED.
  - initiate with zero admitted exhibits → NO_ELIGIBLE_EXHIBITS 422.
  - getJuryPackage before any initiate → { juryPackage: null } and asserts NO JuryPackage row was created (count stays 0).
  - getJuryPackage on a DRAFT after a new exhibit becomes ADMITTED → the new exhibit appears (reconcile adds it).
  - finalizeJuryPackage blocked when an included exhibit has an OPEN flag → JURY_PACKAGE_DISCREPANCIES_OPEN with the blocking exhibit named; after acknowledging that flag, finalize succeeds (status FINALIZED).
  - finalize on an already-FINALIZED package → JURY_PACKAGE_ALREADY_FINALIZED 409.
