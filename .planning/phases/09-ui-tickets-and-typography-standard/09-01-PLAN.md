## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| client→API | `useSearchParams()` values (`status`, `filter`) flow into Case Workspace's `filters`/`quickFilter` client state, then into `searchExhibits`/`getExhibits` fetch query params |
| db→render | `AttentionFeedEntry.summary`/`objectionGrounds` (free-text ledger payload fields) render verbatim into the DataTable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-09-01 | Tampering | `src/app/case/page.tsx` URL-param read | mitigate | `status` read from `searchParams.get('status')` is passed straight into the EXISTING `ExhibitFilters.status` field, which `SearchFilterBar`'s Carbon `Dropdown` only ever submits as one of the 6 fixed `STATUS_OPTIONS` values server-side via `searchExhibits`'s own zod/enum validation (`src/services/exhibits.ts`) — an arbitrary query string value that doesn't match a real status produces zero results, never an injection or crash. `filter` similarly only matches the fixed `QuickFilter` union in `QuickFilterChips.tsx`; any other value falls through to `'all'`. |
| T-09-02 | Information disclosure | `AttentionFeedPanel` DataTable `objectionGrounds`/`summary` render | mitigate | React's default JSX text-node escaping (same posture as `history.ts`'s `summarizeEvent`, threat T-05-05 from Phase 5) — free text is never interpolated into `dangerouslySetInnerHTML`, an href, or an attribute sink. |
