<objective>
Rework the Command Center's Recent Activity panel (T-04 from the external UI/UX review): remove the nested scrollbox that captures the mouse wheel, cap the feed at the latest 10 rows with a "View all" link to a new full activity page, collapse consecutive same-exhibit status transitions within a 60-second window into one summary row, standardize every timestamp to one format including seconds, and fix the heading/date-group-label day-word mismatch.

Purpose: a nested `max-height: 24rem; overflow-y: auto` scrollbox inside a page that is supposed to scroll normally is a known mouse-wheel trap, and a heading that hardcodes the word "today" while the date-group header computes its own day independently is a structural correctness bug, not a cosmetic one.
Output: a page-scrolling panel capped at 10 + View all, grouped rows, one timestamp format, and an agreeing heading/date-group day word.
</objective>

  <name>Task 1: Remove nested scroll, cap at 10 + View all, fix the heading/date-group mismatch</name>
  <files>src/components/command-center/RecentActivityPanel.tsx, src/components/command-center/RecentActivityPanel.module.scss</files>
  <action>
In `RecentActivityPanel.module.scss`: delete `.list`'s `max-height: 24rem; overflow-y: auto;` — the list should flow with the page (confirmed: the page itself has no competing `overflow` rule, so removing this lets the panel scroll normally inside the already-scrollable `<main>`).

In `RecentActivityPanel.tsx`:
1. Render only the first 10 entries of `filteredEntries` (`const visibleEntries = filteredEntries.slice(0, 10);`) and map over `visibleEntries` instead of `filteredEntries` in the list. Below the list (inside the `Tile`, after the `<ul>`), add a "View all" `next/link` to `/activity` (`<Link href="/activity" data-testid="activity-view-all">View all →</Link>`), rendered whenever `entries.length > 0` (regardless of the 10-cap being hit, so the link is always a stable, discoverable affordance — matches "feed shows latest 10 + View all link" literally, not conditionally).
2. Fix the heading/date-group mismatch: the heading currently hardcodes the word "today" (`({entries.length} today)`). Since `getRecentActivity`'s default window is anchored to the START OF DAY of the case's LATEST ledger event (not real wall-clock today), the heading must use the SAME day-word logic the date-group header already computes. Extract a `windowDayWord(iso: string): string` helper from the existing `dateGroupLabel` function (return just `'today'`/`'yesterday'`/the formatted date, lowercased for the heading vs the existing uppercase for the date-group header — reuse the same `dayKey`/`yesterday` comparison, just a different casing/output shape) and call it with `entries[0]?.recordedAt` (the newest entry — since the window is a single calendar day by construction, any entry represents the window's day). Render the heading as `` Recent Activity ({entries.length} {windowDayWord(entries[0]?.recordedAt ?? new Date().toISOString())}) `` — when `entries.length === 0` there is no entry to anchor on; fall back to `'today'` in that case (matches the existing empty-state copy "No activity recorded yet today").
3. Add consecutive same-exhibit grouping: before rendering, derive a new array that walks `filteredEntries` (already sorted newest-first) and merges any RUN of 2+ consecutive entries that share the SAME `exhibitId` AND are all `STATUS_CHANGE` events AND whose `recordedAt` timestamps are all within 60 seconds of the run's first entry, into ONE summary row. The merged row's summary text must read like the ticket's example: `"P-7: marked, offered, objected, admitted"` — build this by extracting each merged entry's resulting status word from its `summary` string is fragile; instead, since `RecentActivityEntry` carries no raw status value, derive the merged label from the FIRST (oldest-in-the-run, i.e. last-in-array-order since newest-first) and LAST (newest) member's existing `summary` strings is also fragile. The robust, minimal approach: render the merged row as `"{exhibitLabel}: {count} status updates"` with a `details`/`<summary>` native HTML disclosure (expandable, per the ticket's "expandable") that lists each individual original summary line when opened — this satisfies "collapse into one summary row, expandable" without needing to parse status words out of free text. Use the entry with the newest `recordedAt` in the run as the row's displayed timestamp. Keep every OTHER entry (not part of a 60s-same-exhibit run) rendered exactly as today.
This merging must happen BEFORE the 10-row slice (a merged row counts as ONE of the 10) and BEFORE the date-group-header walk (so a merged row's single `recordedAt` participates in day-boundary detection normally).
4. Standardize the timestamp: `formatTime` currently omits seconds. Change its `toLocaleString` options to add `second: '2-digit'` so every row (including merged-row timestamps) shows seconds — this is the ONE shared formatter already used for every row in this panel; just extend its options, no second formatter to introduce.
