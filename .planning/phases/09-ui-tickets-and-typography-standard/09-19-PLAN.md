<objective>
Fix the Case Workspace exhibit table's broken row rendering (09-UAT.md test 6, severity major; user: "the case passes but the row in this table needs styled. The rows are broken. fix it").

Root cause, found by live Playwright inspection against the running app (confirmed, not hypothesized): 09-06's `table-layout: fixed` + explicit per-column widths correctly leaves `.colDescription` unset so it SHOULD absorb the table's remaining width — but Carbon's own `.cds--data-table th:last-of-type { inline-size: auto; position: static; }` rule (in the vendored `@carbon/styles` data-table SCSS) overrides `.colChevron { width: 2rem }` on the LAST column (the trailing chevron), because `th:last-of-type` has higher effective specificity than the module's single-class `.colChevron` selector under Carbon's cascade order. The result: BOTH the chevron column AND Description end up competing for "auto" width, splitting the remaining space roughly 50/50 instead of giving it all to Description — collapsing Description to ~96px (measured live: same width as the fixed 6rem Label column) and causing visible mid-word wrapping ("Defendant's / employme..." / "nt's..."). Separately, the Flags column's fixed `10rem` (160px) is narrower than the widest real SeverityPill label ever rendered there ("Ex parte · restricted", measured live at ~165px), so that pill visually overflows ~5-20px past its cell's right edge into the adjacent Jury Package cell, visually colliding with "Not eligible"/"Not yet evaluated" text — exactly the "rows are broken" symptom the user reported.

Both defects were reproduced and the fix validated live (Playwright screenshot evidence) before writing this plan: pinning the chevron column's width with sufficient specificity restores Description's full remainder width, and widening Flags to 13rem (208px) eliminates 100% of the pill overflow across every seeded row including the worst case (S-1, "Ex parte · restricted").

Purpose: a table whose columns visually collide is not "styled," it's broken — this is a pure CSS specificity bug introduced by 09-06's otherwise-correct fixed-layout change, not a data or component-logic defect (the live API data and React rendering logic are both already correct, confirmed via direct API probe and DOM inspection).
Output: every Case Workspace table row renders cleanly at 1440px with no cell-to-cell visual overlap, verified by a new Playwright regression test asserting zero bounding-box overlap between adjacent cells.
</objective>

**Fix 1 — chevron column width.** Carbon's `.cds--data-table th:last-of-type { inline-size: auto; position: static; }` (from the vendored `@carbon/styles` data-table partial) overrides `.colChevron`'s `width: 2rem` because it targets the table's actual LAST column specifically, regardless of this module's single-class selector. Pin the chevron column's width with a selector specific enough to win, using the SAME `.table` class already applied to the `<Table>` root (confirmed present: `<Table className={styles.table}>` in ExhibitTable.tsx) so this stays scoped to this one table, not a global override:

```scss
// Carbon's own `.cds--data-table th:last-of-type { inline-size: auto }` rule
// (vendored @carbon/styles data-table partial) overrides a single-class
// `.colChevron` selector on the table's actual last column, because it
// targets :last-of-type specifically — this silently gave BOTH the chevron
// column AND Description "auto" width under table-layout:fixed, splitting
// the remainder ~50/50 instead of letting Description absorb it all (the
// 09-06 defect this fixes, confirmed via live Playwright measurement: the
// Description column was collapsing to the same ~96px as the fixed 6rem
// Label column). Compound the selector with the table's own class to win
// without reaching for a global :last-of-type override or !important.
.table :global(.cds--data-table) th:last-of-type.colChevron,
.table :global(.cds--data-table) td:last-of-type.chevronCell {
  inline-size: 2rem;
  width: 2rem;
}
```

(Both `inline-size` and the legacy `width` property are set because Carbon's own rule sets `inline-size`, and this module's existing `.col*` rules all use `width` — setting both guarantees whichever property wins in the cascade still lands on 2rem.)

**Fix 2 — Flags column width.** `.colFlags`'s current `10rem` (160px) is narrower than the widest real SeverityPill content ever rendered there. Live-measured pill widths across every pill label currently in use: "Ruling pending" 125px, "Open objection" 129px, "No custodian" 120px, "Ex parte · restricted" **165px** (the overflow case, confirmed live on the S-1 seeded row). Widen `.colFlags` to `13rem` (208px — comfortably clears the widest pill plus its stacked-pill `.flagStack` padding/gap):

```scss
.colFlags {
  width: 13rem; // was 10rem — too narrow for "Ex parte · restricted" (~165px
  // measured live), causing the pill to visually overflow into the adjacent
  // Jury Package column (the "rows are broken" UAT-6 gap-closure defect).
}
```

```typescript
test('exhibit table rows render with zero cell-to-cell visual overlap at 1440px, including a row with multiple stacked Flags pills (UAT-6 gap closure)', async ({ page }) => {
  await page.setViewportSize({ width: 1440, height: 900 });
  await page.goto('/case');
  await page.waitForSelector('[data-testid="exhibit-row"]');

  // Every row's Flags cell and Jury Package cell must not visually overlap —
  // this is the exact failure mode reported ("rows are broken"): a wide
  // SeverityPill (e.g. "Ex parte · restricted") spilling past its own
  // column's right edge into the next cell's text.
  const rows = page.locator('[data-testid="exhibit-row"]');
  const rowCount = await rows.count();
  for (let i = 0; i < rowCount; i++) {
    const row = rows.nth(i);
    const cells = row.locator('td');
    const flagsCell = cells.nth(5); // Label, Description, Party, Status, Custodian, Flags, Jury, chevron
    const juryCell = cells.nth(6);
    const pill = flagsCell.locator('[data-testid="severity-pill"]').first();
    if (await pill.count() > 0) {
      const pillBox = await pill.boundingBox();
      const juryBox = await juryCell.boundingBox();
      expect(pillBox).not.toBeNull();
      expect(juryBox).not.toBeNull();
      // The pill's right edge must not cross into the Jury Package cell's
      // left edge — zero horizontal overlap.
      expect(pillBox!.x + pillBox!.width).toBeLessThanOrEqual(juryBox!.x + 1);
    }
  }

  // The Description column must be meaningfully wider than the fixed-width
  // Label column (the 09-06 defect collapsed it to the SAME width as Label,
  // ~96px, instead of absorbing the table's true remainder).
  const firstRow = rows.first();
  const labelCellWidth = (await firstRow.locator('td').nth(0).boundingBox())!.width;
  const descCellWidth = (await firstRow.locator('td').nth(1).boundingBox())!.width;
  expect(descCellWidth).toBeGreaterThan(labelCellWidth * 1.5);
});
```
