<objective>
Make the demo role switcher unmistakable (T-09 from the external UI/UX review): label it clearly as a demo/test control (and env-flag-gate it so a hypothetical future real-auth deployment can turn it off without code changes), add a persistent "Active role: X — switch back" banner after switching, and confirm every role-gated query already refetches immediately on switch (it already does — this plan verifies and documents that, rather than re-implementing it).

Purpose: a role switcher styled like an ordinary dropdown but silently changing what the user can do is a genuine safety hazard in a courtroom-facing demo if mistaken for a real account menu; per 09-CONTEXT decision #1, this plan does NOT build a centralized `assertRole` helper or extend role gating to any currently-ungated write path — that is explicitly deferred (Phase 7.1) scope.
Output: a labeled, optionally-gated switcher, a persistent active-role banner, and a confirmed-already-correct query-key-refresh guarantee.
</objective>
