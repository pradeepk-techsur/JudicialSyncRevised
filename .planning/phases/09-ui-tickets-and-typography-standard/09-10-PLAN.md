<objective>
Build F25's new read-only Jury Package Readiness Preview (T-10 from the external UI/UX review): a new `getJuryPackageReadinessPreview` service function computing, for every currently-ADMITTED exhibit visible to the requesting role, whether it is ready for the jury package and — if not — which specific blocker(s) apply (`UNRESOLVED_OBJECTION`, `NO_CUSTODIAN`, `SEALED_EXPARTE`), exposed via a new dedicated route and rendered identically, read-only, for EVERY role including JUDGE — who cannot start or finalize a package but can now see readiness at a glance. The Jury Package empty state is rebuilt to span the full content width and name which roles can start a package.

Purpose: today readiness information only exists by actually starting a draft, which a JUDGE (and other non-starting roles) structurally cannot do — this closes that visibility gap with a function that creates nothing, ever.
Output: a new pure-read service function + route + hook + always-visible preview panel + a rebuilt full-width empty state.
</objective>

Add to `src/services/juryPackage.ts` a new exported function:
```ts
export async function getJuryPackageReadinessPreview(
  caseId: string,
  requestingUserRole: Role,
): Promise<{
  preview: Array<{
    exhibitId: string;
    exhibitLabel: string;
    ready: boolean;
    blockers: Array<{ code: 'UNRESOLVED_OBJECTION' | 'NO_CUSTODIAN' | 'SEALED_EXPARTE'; detail: string }>;
  }>;
  summary: { totalAdmitted: number; readyCount: number; blockedCount: number };
}>
```
Implementation (performs NO write under any circumstance — no `JuryPackage`/`JuryPackageExhibit` row is ever created, updated, or referenced):
1. Query every exhibit with `currentStatus = 'ADMITTED'` in this case, applying the SAME `canViewSealed(requestingUserRole)` WHERE predicate every other role-scoped read in this codebase uses (`src/services/visibility.ts`) — a sealed exhibit a role cannot see at all is OMITTED from the list entirely, never shown as a masked/blocked row (anti-enumeration, matching the 404-masking principle already applied elsewhere).
2. For each visible admitted exhibit, directly query — reusing the IDENTICAL underlying conditions `evaluateDiscrepancies`'s rule registry already checks in `src/services/discrepancies.ts` (read that file's `RULES`/`ProjectionSnapshot` first — this function must check the SAME `hasCustody`/`unresolvedObjectionCount` conditions, not invent new ones): `custodyCurrentState.findUnique({ where: { exhibitId } })` for custody presence, `objectionCurrentState.count({ where: { exhibitId, status: 'UNRESOLVED' } })` for unresolved objections, and the exhibit's own `isSealed` flag (already in hand from step 1's query).
3. Blockers (an exhibit may carry more than one simultaneously — check ALL, don't short-circuit on the first match): `isSealed === true` → `{ code: 'SEALED_EXPARTE', detail: 'Sealed/ex parte material cannot be included in a jury package' }`; `custody === null` → `{ code: 'NO_CUSTODIAN', detail: 'No custodian of record' }`; `unresolvedObjectionCount > 0` → `{ code: 'UNRESOLVED_OBJECTION', detail: 'An objection on this exhibit is still unresolved' }`. `ready = blockers.length === 0`.
4. Return `{ preview, summary: { totalAdmitted: preview.length, readyCount: preview.filter(p=>p.ready).length, blockedCount: preview.filter(p=>!p.ready).length } }`. No pagination.

This function performs NO role gate of its own (F25: every role gets 200, never 403 — unlike `initiateJuryPackage`'s `assertJuryWriteRole`) — do NOT call `assertJuryWriteRole` or any similar check here.

Add `JuryPackagePreviewLoadError` to `src/lib/errors.ts` following the EXACT existing pattern (`class JuryPackagePreviewLoadError extends AppError { constructor() { super('JURY_PACKAGE_PREVIEW_LOAD_FAILED', 'Unable to load the jury package readiness preview — please retry', 500); } }` — mirror `AttentionFeedLoadError`'s shape exactly).

Create `src/app/api/cases/[id]/jury-package/preview/route.ts` with a `GET` handler: parse `caseId` from params, `requestingUserRole` via `parseRequestingRole(request)`, call `getJuryPackageReadinessPreview`, return 200 with the result; on any non-`AppError` failure, wrap in `JuryPackagePreviewLoadError` — mirror `src/app/api/cases/[id]/attention-feed/route.ts`'s exact error-handling shape (it was written for precisely this situation).
