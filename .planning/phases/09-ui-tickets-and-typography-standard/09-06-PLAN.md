<objective>
Fix the Case Workspace's jury-package eligibility column at its ROOT (T-06 from the external UI/UX review): today `loadJuryEligibilityByExhibit` collapses "no package ever computed" and "structurally excluded" into one `NOT_ELIGIBLE` value, so every exhibit reads "Not eligible" until a package is initiated. Split this into a 4-value precedence per FRD `F09-case-workspace-screen.md` (`INCLUDED` / `BLOCKED` / `NOT_ELIGIBLE` reserved for a structural exclusion / `NOT_YET_EVALUATED` for "no row exists yet"), fixed in the SERVICE layer so every consumer (`getExhibits`, `searchExhibits`, `getExhibitHistory`'s checklist) stays in lockstep by construction. Also widen the Description column, remove zebra striping, and gate "Add exhibit" to DEPUTY/CLERK/ADMIN.

Purpose: a column that always reads "Not eligible" regardless of whether an exhibit has even been admitted yet is actively misleading — it looks like a permanent verdict when it is really just "nobody has checked."
Output: a 4-value eligibility precedence computed once in the service layer, rendered correctly (including "show nothing" for non-admitted rows) everywhere it appears.
</objective>

Per FRD `F09-case-workspace-screen.md` §Process step 3 (read it first — it is fully authoritative for this exact function), the precedence is: `INCLUDED` = INCLUDED member row with `discrepancyStatus='CLEAN'`; `BLOCKED` = INCLUDED member row with `discrepancyStatus='FLAGGED'`; `NOT_ELIGIBLE` = a *structural, permanent* exclusion — an `EXCLUDED` member row, **or** the exhibit is sealed (`isSealed=true`, the established Phase-8 substitute for F16's non-existent `classification` column — confirm via `grep -n "isSealed" src/services/attentionFeed.ts` for the precedent pattern already used in this codebase); `NOT_YET_EVALUATED` = every other case (no member row exists for this exhibit at all — covers not-yet-ADMITTED, ADMITTED-but-no-package-ever-computed, and ADMITTED-after-the-latest-package's-computation).

In `src/services/exhibits.ts`, rewrite `loadJuryEligibilityByExhibit(caseId, exhibitIds)`:
1. Widen its return type to `Map<string, 'INCLUDED' | 'BLOCKED' | 'NOT_ELIGIBLE' | 'NOT_YET_EVALUATED'>`.
2. Additionally batch-fetch each exhibit's `isSealed` flag (one extra `prisma.exhibit.findMany({ where: { id: { in: exhibitIds } }, select: { id: true, isSealed: true } })` — the function doesn't currently need exhibit rows at all, only `juryPackageExhibit` rows, so this is a genuinely new query, batched once, not per-row).
3. For each `exhibitId`: if `isSealed` → `NOT_ELIGIBLE` (structural, regardless of row existence or package state). Else if no `latestPackage` exists at all, or no member row exists for this exhibit → `NOT_YET_EVALUATED` (replacing the current function's "no package → NOT_ELIGIBLE for everyone" branch). Else if the member row's `status === 'EXCLUDED'` → `NOT_ELIGIBLE`. Else if `discrepancyStatus === 'FLAGGED'` → `BLOCKED`. Else → `INCLUDED`.
Update the function's JSDoc to document the Phase 9 precedence change and the `isSealed` substitution, same style as the existing comment already explaining the EXPORTED/single-implementation contract — keep that contract statement intact (this is still the ONE implementation; `history.ts`'s checklist MUST keep calling this function, never re-derive).
