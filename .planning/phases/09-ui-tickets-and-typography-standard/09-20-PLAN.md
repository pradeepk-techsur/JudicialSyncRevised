<objective>
Close two related UAT gaps in the shared app shell's header/role-switcher area, both confirmed via live Playwright inspection against the running app before this plan was written:

**UAT-9 (major):** After switching the demo role, the persistent "Active role: X — switch back" banner's TEXT is hidden behind the fixed sidebar. Root cause (confirmed live, not hypothesized): `ActiveRoleBanner` renders in normal document flow between `Header` and `.body` with NO horizontal offset, but `Sidebar`'s `<nav>` is `position: fixed; inset-block-start: 3rem` (48px, matching the header height) with `z-index: 8000` and spans the full `16rem` rail width — so the fixed sidebar paints directly over the banner's first 16rem of content, hiding "Active role: {name} ({role})" entirely (only text past the sidebar's right edge, like "Switch back to...", remains visible). This is the SAME root-cause *class* as 08-16's sidebar/header z-index fix, but NOT the same fix: 08-16 fixed a *vertical* overlap between the sidebar and header (two fixed elements both starting at y=0); this is a *horizontal* overlap between the fixed sidebar and an in-flow banner that never accounted for the sidebar's rail width at all. Fix: give the banner the same `16rem` left inset `AppShell.module.scss`'s `.body` and `Sidebar.module.scss`'s dark-nav styling already use as their shared rail-width constant, so the banner's content starts exactly where the sidebar ends.

**UAT-16 (minor):** The user explicitly asked to (1) drop the visible "Demo role:" label text and (2) left-align the role-switcher dropdown so its left edge matches the page title's left edge (e.g. "Trial Command Center"). Fix (validated live): set Carbon's `Select` `hideLabel` prop (keeping the existing `aria-label="Switch active role"` — every Playwright test targets this accessible name, unaffected by `hideLabel`) and absolutely-position the switcher's form-item at the SAME horizontal offset every page title's own box already renders at (`16rem` sidebar + `1.5rem` main padding = `17.5rem` from the viewport edge, confirmed live to produce an EXACT pixel match with `h1`'s left edge on Command Center and Case Workspace).

Purpose: both are shell-layout bugs with precise, already-validated CSS fixes — no data, API, or role-permission change of any kind.
Output: the active-role banner is fully readable after every role switch; the role switcher has no visible redundant label and its dropdown aligns with the page title, exactly as requested.
</objective>

```typescript
test('the active-role banner text is NOT obscured by the sidebar after a role switch (UAT-9 gap closure)', async ({ page }) => {
  await page.goto('/case');
  const select = page.getByLabel('Switch active role');
  const deputyOption = select.locator('option', { hasText: '(DEPUTY)' });
  const deputyValue = (await deputyOption.getAttribute('value')) as string;
  await select.selectOption(deputyValue);

  const banner = page.getByTestId('active-role-banner');
  await expect(banner).toBeVisible();

  const nav = page.getByRole('navigation', { name: 'Main navigation' });
  const navBox = await nav.boundingBox();
  const labelBox = await banner.locator('span').first().boundingBox();
  expect(navBox).not.toBeNull();
  expect(labelBox).not.toBeNull();
  // The banner's own label text must start AT OR AFTER the sidebar's right
  // edge — zero horizontal overlap between the two.
  expect(labelBox!.x).toBeGreaterThanOrEqual(navBox!.x + navBox!.width - 1);

  // Stronger check: hit-test the actual rendered center of the banner's
  // label text and confirm the SIDEBAR isn't the topmost element there
  // (mirrors the existing sidebar/header overlap test's hit-test pattern).
  const centerX = labelBox!.x + labelBox!.width / 2;
  const centerY = labelBox!.y + labelBox!.height / 2;
  const topElementTag = await page.evaluate(
    ({ x, y }) => document.elementFromPoint(x, y)?.closest('nav') ? 'nav' : document.elementFromPoint(x, y)?.tagName ?? null,
    { x: centerX, y: centerY },
  );
  expect(topElementTag).not.toBe('nav');
});
```
