<objective>
Raise text contrast and enforce the minimum text-size rule across the four main screens (T-12 from the external UI/UX review), now that every P1/P2 ticket's UI changes have landed in this phase: audit and replace custom/raw grey color values used for timestamps, helper text, and sub-labels with Carbon's `text-secondary`/`text-helper` tokens, confirm every such text node is at least `body-compact-01` (14px) with 12px reserved strictly for tags/labels/field-helper text, and add an automated axe accessibility scan proving zero contrast failures.

Purpose: small, light-grey text on grey panels is unreadable in a courtroom's variable lighting, and this ticket intentionally runs LAST among the structural tickets so it audits the FINAL rendered state of every screen this phase touches, not an intermediate one that would need re-auditing after each subsequent ticket. The contrast check is implemented with ZERO new dependency — this phase's constraint is "no npm dependency beyond next/font" (09-CONTEXT.md), so this plan does NOT add `@axe-core/playwright` or any other accessibility-audit package; it reuses the exact locally-implemented WCAG contrast-ratio pure function 09-02 already wrote for SeverityPill's four tones, applied more broadly.
Output: token-based text colors app-wide, a passing locally-computed contrast sweep proving >=4.5:1 on every audited pair across all 4 main pages, with zero new dependency.
</objective>
