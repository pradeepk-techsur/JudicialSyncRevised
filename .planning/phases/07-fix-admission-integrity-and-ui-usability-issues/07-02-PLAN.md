<objective>
F12's admission gate (plan 07-01) now rejects any `ADMITTED` transition on an exhibit with an unresolved objection or no custodian — for EVERY caller, including the seed loader. The current `seed.ts` deliberately constructs exactly these two conditions on ALREADY-ADMITTED exhibits (to demonstrate F6's discrepancy engine), and several pre-existing test fixtures across the codebase do the same thing incidentally (establishing custody AFTER admitting, for narrative convenience). All of this now throws under the new gate. This plan makes the seed loader and every affected pre-existing test fixture compliant with the gate, while preserving F0a's original "unresolved objection / custody gap / jury-package discrepancy demonstrable out of the box" guarantee in a shape the new gate allows.

Purpose: Without this plan, Docker boot (`migrate -> seed -> serve`) fails outright the moment plan 07-01 lands, and roughly a dozen pre-existing tests across the suite go red — breaking the entire demo, not just the new feature.
Output: A seed loader whose every ADMITTED transition is gate-compliant, redefined demo edge cases that showcase the GATE itself rather than a now-impossible post-admission flag, staggered seed timestamps (F15 item 6), and a fully green pre-existing test suite.
</objective>

// (plan 07-01) now forbids reaching ADMITTED with no custodian or an open
// objection for EVERY real caller — by design. This helper exists ONLY so
// tests that are specifically exercising discrepancy-flag / acknowledge /
// finalize-gate behavior (not the admission gate itself) can still construct
// a genuinely-firing precondition: it directly appends a STATUS_CHANGE ledger
// event and upserts ExhibitCurrentState to ADMITTED, bypassing the gate, then
// calls evaluateDiscrepancies so the resulting flag is REAL (survives any

// re-evaluation would silently resolve away.
async function forceAdmitBypassingGate(
  exhibitId: string,
  caseId: string,
  actorUserId: string,
): Promise<void> {
  const agg = await prisma.exhibitEvent.aggregate({
    where: { exhibitId },
    _max: { sequenceNo: true },

  const event = await prisma.exhibitEvent.create({
    data: {
      exhibitId,
      caseId,
      eventType: 'STATUS_CHANGE',

      actorUserId,
      sequenceNo: (agg._max.sequenceNo ?? 0) + 1,

    where: { exhibitId },
    create: { exhibitId, currentStatus: 'ADMITTED', lastStatusEventId: event.id, lastStatusAt: event.recordedAt },
    update: { currentStatus: 'ADMITTED', lastStatusEventId: event.id, lastStatusAt: event.recordedAt },
