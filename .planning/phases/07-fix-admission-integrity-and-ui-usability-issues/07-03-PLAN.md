**Current `computeJuryCandidates` (the function to amend — exact current body, already read from the live repo):**
```typescript
export async function computeJuryCandidates(
  caseId: string,
  // eslint-disable-next-line @typescript-eslint/no-unused-vars
  requestingUserRole: Role,
  client?: PrismaLike,
): Promise<JuryCandidate[]> {
  const db = client ?? prisma;
  const rows = await db.exhibitCurrentState.findMany({
    where: { currentStatus: 'ADMITTED', exhibit: { caseId } },
    select: {
      exhibit: { select: { id: true, exhibitLabel: true, isSealed: true } },
    },
    orderBy: { exhibit: { exhibitLabel: 'asc' } },
  });
  return rows.map((r) => ({
    exhibitId: r.exhibit.id,
    exhibitLabel: r.exhibit.exhibitLabel,
    currentStatus: 'ADMITTED' as const,
    isSealed: r.exhibit.isSealed,
  }));
}
```
This function already carries `isSealed` on each candidate for VIEW-layer filtering (`toView()` drops sealed rows a role can't see) — but does NOT currently exclude sealed exhibits from MEMBERSHIP itself. The file's header comment currently documents this as an intentional "membership is case truth regardless of seal" design — that comment is WRONG after this plan and must be corrected/removed.

**Current `reconcileDraftMembership` (the function to amend — exact current body, already read from the live repo):**
```typescript
async function reconcileDraftMembership(
  caseId: string,
  juryPackageId: string,
): Promise<{ members: JuryCandidate[]; addedAtByExhibit: Map<string, Date> }> {
  const candidates = await computeJuryCandidates(caseId, 'ADMIN' /* full-visibility lens */);
  const candidateIds = new Set(candidates.map((c) => c.exhibitId));

  const existingRows = await prisma.juryPackageExhibit.findMany({
    where: { juryPackageId },
    select: { id: true, exhibitId: true, addedAt: true },
  });
  const existingByExhibit = new Map(existingRows.map((r) => [r.exhibitId, r]));

  // Remove rows for exhibits no longer ADMITTED.
  const staleRowIds = existingRows
    .filter((r) => !candidateIds.has(r.exhibitId))
    .map((r) => r.id);

  const newCandidates = candidates.filter((c) => !existingByExhibit.has(c.exhibitId));

  await prisma.$transaction(async (tx) => {
    if (staleRowIds.length > 0) {
      await tx.juryPackageExhibit.deleteMany({ where: { id: { in: staleRowIds } } });
    }
    for (const c of newCandidates) {
      const { discrepancyStatus } = await liveFlags(c.exhibitId);
      await tx.juryPackageExhibit.create({ data: { juryPackageId, exhibitId: c.exhibitId, discrepancyStatus } });
    }
    for (const c of candidates) {
      if (existingByExhibit.has(c.exhibitId)) {
        const { discrepancyStatus } = await liveFlags(c.exhibitId);
        await tx.juryPackageExhibit.updateMany({ where: { juryPackageId, exhibitId: c.exhibitId }, data: { discrepancyStatus } });
      }
    }
  });

  const finalRows = await prisma.juryPackageExhibit.findMany({ where: { juryPackageId }, select: { exhibitId: true, addedAt: true } });
  const addedAtByExhibit = new Map(finalRows.map((r) => [r.exhibitId, r.addedAt]));
  return { members: candidates, addedAtByExhibit };
}
```
**The bug this plan must fix here:** once `computeJuryCandidates` excludes sealed exhibits, a LEGACY `JuryPackageExhibit` row for a sealed exhibit that is STILL genuinely `ADMITTED` (just now excluded from `candidates` because it's sealed) would incorrectly be treated as "no longer admitted" by `staleRowIds`'s `!candidateIds.has(r.exhibitId)` check — and get DELETED. F13 explicitly requires this row to be RETAINED (never deleted), so it can render the CRITICAL warning and be explicitly excluded later. Fix: compute staleness from the exhibit's ACTUAL `currentStatus` (a direct, unfiltered query), not from absence-from-`candidates` (which now conflates "no longer admitted" with "admitted but sealed").
