```typescript
export async function getExhibitHistory(exhibitId: string): Promise<{
  exhibit: Exhibit;
  currentStatus: ExhibitStatus | null;
  currentCustodianName: string | null;
  discrepancyFlags: [];  // always empty in Phase 1 — Phase 3 populates this field once DiscrepancyFlag exists
  timeline: Array<{
    eventId: string;
    eventType: EventType;
    summary: string;
    actorName: string;
    recordedAt: string;
  }>;
} | null>
```

Implementation:
1. Fetch the `Exhibit` (via `getExhibit` from Plan 2) — return `null` if not found (API route maps to 404).
2. Fetch `ExhibitCurrentState` and `CustodyCurrentState` (joined to the custodian's `User.name`) for the header summary fields.
3. Fetch ALL `ExhibitEvent` rows for this exhibit, `orderBy: { sequenceNo: 'asc' }` — no filtering by `eventType`, no truncation, no "recent N" limiting (per F10 §Validation/US-10.1: "complete history, not 'recent N events'").
4. For each event, join `actorUserId` → `User.name` and translate the raw `eventType`/`payload` into a plain-language `summary` string:

   - `RULING_RECORDED`: `"Ruling recorded: {disposition}"`
   - `CUSTODY_TRANSFER`: `"Custody transferred from {fromCustodian name or '(none)'} to {toCustodian name}{reason ? ' — ' + reason : ''}"`
   - `DISCREPANCY_ACKNOWLEDGED`: `"Discrepancy acknowledged: {justification}"` (dead code path in Phase 1 — no such events exist yet — but included for completeness since the enum value exists in the schema).

<task type="auto">
  <name>Task 2: Projection rebuild + live-vs-rebuilt consistency verification</name>
  <files>src/services/rebuild.ts, src/services/rebuild.test.ts</files>
  <action>
Create `src/services/rebuild.ts` per TechArch §3.8 "Projection Integrity" / FRD F00 §Process step 7:

```typescript
export async function rebuildProjections(caseId: string): Promise<{
  matches: boolean;
  diffs: Array<{ exhibitId: string; field: string; live: unknown; rebuilt: unknown }>;
}>
```

Implementation (read-only admin/dev utility — this function NEVER writes to any projection table; it only computes an in-memory reconstruction and diffs it against the live tables):
1. For every `Exhibit` in the case, fetch its full `ExhibitEvent` list `orderBy: { sequenceNo: 'asc' }`.
2. Replay in memory to compute what each projection SHOULD be:
   - Walk `STATUS_CHANGE` events in order; the last one's `payload.toStatus` is the rebuilt `currentStatus`, its `id`/`recordedAt` are the rebuilt `lastStatusEventId`/`lastStatusAt`. No events of this type → rebuilt state is "absent" (matches `ExhibitCurrentState` having no row).
   - Group `OBJECTION_RAISED`/`RULING_RECORDED` events by `payload.objectionId`; for each thread, the rebuilt `status` is `UNRESOLVED` unless a `RULING_RECORDED` with `disposition` `SUSTAINED` or `OVERRULED` exists for that thread (a `RESERVED` ruling does NOT close it), in which case the rebuilt status is that disposition.
   - Walk `CUSTODY_TRANSFER` events in order; the last one's `payload.toCustodianUserId` is the rebuilt current custodian. No events → rebuilt state is "absent."
3. Fetch the LIVE `ExhibitCurrentState`, `ObjectionCurrentState`, `CustodyCurrentState` rows for the same case.
4. Compare rebuilt vs. live, field by field, for every exhibit and every objection thread. Record every mismatch as a `{ exhibitId, field, live, rebuilt }` diff entry. `matches: true` iff `diffs` is empty.

This function is read-only by design (TechArch §3.8: "should be run as a pre-demo sanity check, not relied upon as a live write path") — it must not call `recordEvent` or write to any `*CurrentState` table under any circumstance.

Write `src/services/rebuild.test.ts` against the REAL seeded case (`runSeed()` in `beforeAll`):
- Call `rebuildProjections(caseId)` immediately after seeding; assert `matches === true` and `diffs` is empty — this is the direct proof of Phase 1 success criterion 5 ("rebuilding current-state projections from scratch by replaying the ledger produces results identical to the live projections").
- Negative-control sanity check: directly (via raw Prisma, test-only) corrupt one exhibit's `ExhibitCurrentState.currentStatus` to an intentionally wrong value, re-run `rebuildProjections`, and assert it now correctly reports `matches: false` with a diff entry identifying exactly that exhibit/field — proving the comparison logic actually detects divergence rather than trivially always passing.
