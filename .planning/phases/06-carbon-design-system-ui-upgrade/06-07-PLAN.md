CRITICAL constraint directly asserted by the test suite (lines ~106-108 of command-center.spec.ts):
```
await expect(cc.locator('form')).toHaveCount(0);
await expect(cc.locator('input')).toHaveCount(0);

```
This means NONE of Carbon's form-control components (`TextInput`, `Search`, `TextArea`, `Dropdown`'s hidden input, etc.) may appear ANYWHERE within the Command Center's root test container (`data-testid="command-center"`). This screen only ever needs read-only display components: `Tile`, `SkeletonText`/`SkeletonPlaceholder` (loading), `InlineNotification` (errors, with a `Button`-rendered "Retry" — a `<button>` element is fine, `<form>`/`<input>`/`<textarea>` are not), `Tag` (discrepancy count badge), and plain text/`Link`. Do not reach for any Carbon component that renders a hidden `<input>` internally (e.g. do NOT use `Search` as a decorative non-functional element, do NOT use any Dropdown/Select here even for display purposes).

Carbon components relevant here:
- `Tile` — simple bordered container, replaces the current `rounded-lg border bg-white p-4` div wrapper for each panel.
- `SkeletonText` / `SkeletonPlaceholder` — Carbon's literal loading-skeleton components, a direct semantic upgrade over the current hand-rolled `animate-pulse` divs (same visual intent, now a first-class Carbon pattern — see carbondesignsystem.com Building Blocks → Patterns → "Loading").
- `InlineNotification` — `kind="error"` for the retry-able error states (each panel's own, per the "error isolation" Phase 5 criterion — one panel's InlineNotification must not affect the others), `lowContrast` + `hideCloseButton` props available if a persistent (non-dismissible) inline banner is wanted; since these errors are transient (resolve themselves once the next poll succeeds), allow the default dismissible chrome OR set `hideCloseButton` — either is acceptable, pick based on keeping the existing "Retry" link inline within the notification's `actionButtonLabel` slot or as a child action.
