<objective>
Close the one open UAT gap on Phase 8 (`08-UAT.md` test **"2. Command Center — Stat Cards & Status Distribution"**, gap ref **"2"**, severity major): the dark-navy sidebar visually overlaps the shared header's role-switcher dropdown, and the Command Center's status-distribution widget renders as a loud multi-colored segmented bar the user wants gone.

Root cause (independently verified against the vendored Carbon v1.117.0 `@carbon/styles` UI-shell source, not assumed from the UAT's own hypothesis): Carbon's `_side-nav.scss` ships a sibling-combinator rule, `.cds--header ~ .cds--side-nav { inset-block-start: mini-units(6); block-size: calc(100% - 48px); }`, that is the ONLY mechanism by which Carbon's SideNav learns to clear the fixed Header's 48px band — and it fires ONLY when `.cds--side-nav` is a literal next DOM sibling of `.cds--header`. In this app's `AppShell.tsx`, `<Header />` and the `<Sidebar />`-containing `<div className={styles.body}>` ARE siblings, but `Sidebar.tsx`'s own rendered `.cds--side-nav` node is nested two levels inside that sibling `<div>`, so the selector never matches. Confirmed from `SideNav.js`'s own prop logic that `isChildOfHeader={false}` (set explicitly in `Sidebar.tsx`) suppresses the only OTHER Carbon class (`--side-nav--ux`) that would have applied a `$spacing-09` top offset. Net effect: `.cds--side-nav`'s own base rule, `inset-block: 0` (top:0, bottom:0), wins — the side-nav is a `position: fixed` element starting at viewport y=0, the SAME y origin as the equally-`position:fixed`, equal-`z-index:8000` Header — and because neither `.shell` nor `.body` establishes a stacking context (no `position`, `transform`, `opacity<1`, or `filter` on either), both fixed elements resolve in the SAME (root) stacking context, where equal z-index ties break by DOM order: Sidebar's subtree is later in document order than Header, so it paints on top across their entire geometric overlap (x:0–16rem, y:0–3rem) — covering the Header's left portion unconditionally, and depending on exact header content wrapping at the tested viewport, visually colliding with (or crowding) the role-switcher region the user flagged. The fix: give the sidebar panel the exact offset Carbon's own sibling rule would have applied had the DOM matched — `inset-block-start: 3rem` (matching `AppShell.module.scss`'s own documented `.shell { padding-top: 3rem }` header-height constant) + `block-size: calc(100% - 3rem)` — so the side-nav never occupies the header's y-band at all, eliminating the overlap regardless of z-index tie-breaking. This is a single-file, CSS-only change; no DOM restructuring (confirmed unnecessary and higher-risk per the investigation).

The second gap item is a locked, pre-decided scope cut, not an investigation: remove `StatusDistributionBar`'s `.bar`/`.segment`/`.emptyBar` segmented-color markup entirely; keep its `.legend` (`data-testid="status-distribution-legend"`) exactly as-is — a plain dot+label+count row per status, already the non-loud, already-shipped half of the component.

Purpose: these are the only two items blocking Phase 8 from being UAT-clean; both are presentation-only fixes against already-shipped (08-04, 08-10) code, requiring no new data flow.
Output: corrected Sidebar CSS (no header overlap, durable Playwright regression test), simplified StatusDistributionBar (legend-only), updated e2e assertions for both.
