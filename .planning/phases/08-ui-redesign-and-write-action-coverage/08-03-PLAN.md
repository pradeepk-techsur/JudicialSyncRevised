**SeverityPill** — the ONE component for both attention-feed tier badges AND condition/flag pills (Case Workspace Flags column, Jury Package condition pills), per `Y0-patterns.md` §Severity Tier Badge + §Readable Flag Pill ("one pill component, color+text convention shared"):

```tsx
export type SeverityTone = 'critical' | 'high' | 'pending' | 'medium';

const TONE_CONFIG: Record<SeverityTone, { bg: string; fg: string; tierWord: string }> = {
  critical: { bg: styles.toneCritical, fg: styles.toneCriticalFg, tierWord: 'Critical' },
  high:     { bg: styles.toneHigh,     fg: styles.toneHighFg,     tierWord: 'High' },
  pending:  { bg: styles.tonePending,  fg: styles.tonePendingFg,  tierWord: 'Pending' },
  medium:   { bg: styles.toneMedium,   fg: styles.toneMediumFg,   tierWord: 'Medium' },
};

export function SeverityPill({
  tone,
  label,
  ariaLabel,
}: {
  tone: SeverityTone;
  label: string;
  ariaLabel?: string;
}) {
  const cfg = TONE_CONFIG[tone];
  return (
    <span
      className={`${styles.pill} ${cfg.bg}`}
      data-testid="severity-pill"
      data-tone={tone}
      aria-label={ariaLabel ?? `Severity: ${cfg.tierWord}`}
    >
      {label}
    </span>
  );
}
```

Color mapping (CSS Module, fixed per `00-overview.md` §Visual Foundation): `critical` = dark red bg / white text, `high` = amber bg / dark text, `pending` = amber-light (lighter/desaturated amber, visually distinct from `high` at a glance) bg / dark text, `medium` = yellow bg / dark text. The tier word or condition text is ALWAYS the visible `label` prop (caller passes either a tier word like "Critical" for the attention feed, or a condition phrase like "Unresolved objection"/"No custodian on record"/"Critical · ex parte material"/"Ruling pending"/"Open objection"/"Ex parte · restricted" for condition pills) — color is NEVER the sole signal (Y2-accessibility.md "never color alone"). `ariaLabel` defaults to the tier-word form but callers rendering a condition pill should pass an explicit one (e.g. `aria-label="Flag: No custodian on record"`).

**TwoColorProgressBar** — the one "clean vs. blocked" bar, rendering the IDENTICAL `{clean}/{total}` ratio wherever consumed (Command Center's Jury Package summary widget AND the Jury Package Workspace's own header bar read the same source data, per the locked standardization decision):

```tsx
export function TwoColorProgressBar({ clean, total }: { clean: number; total: number }) {
  const blocked = Math.max(0, total - clean);
  const cleanPct = total > 0 ? Math.round((clean / total) * 100) : 0;
  return (
    <div className={styles.container} data-testid="two-color-progress-bar">
      <div
        className={styles.track}
        role="progressbar"
        aria-valuenow={cleanPct}
        aria-valuemin={0}
        aria-valuemax={100}
        aria-label={`${clean} of ${total} exhibits are clean`}
      >
        <div className={styles.cleanSegment} style={{ width: `${cleanPct}%` }} />
        <div className={styles.blockedSegment} style={{ width: `${100 - cleanPct}%` }} />
      </div>
      <p className={styles.caption} data-testid="two-color-progress-caption">
        {clean} of {total} exhibits are clean
        {blocked > 0 ? ` · ${blocked} blocker${blocked === 1 ? '' : 's'} remain` : ''}
      </p>
    </div>
  );
}
```
Handle `total === 0` without NaN (early-return a 0% bar, caption reads "0 of 0 exhibits are clean").

**Card** — the shared card-chrome wrapper (rounded-corner white card on the light content area; red left-border/outline when `critical`):

```tsx
export function Card({
  critical,
  children,
  className,
  ...rest
}: { critical?: boolean; children: ReactNode; className?: string } & React.HTMLAttributes<HTMLDivElement>) {
  return (
    <div
      className={`${styles.card} ${critical ? styles.critical : ''} ${className ?? ''}`}
      data-testid="dashboard-card"
      data-critical={critical ? 'true' : 'false'}
      {...rest}
    >
      {children}
    </div>
  );
}
```
CSS: rounded corners (match Carbon `Tile`'s dark-dashboard corner-radius per `00-overview.md`), white background, subtle elevation/shadow; `.critical` variant adds a 3-4px solid red left border, applied identically regardless of consumer (attention-feed entry, Jury Package blocker card, any future card-shaped surface).

**ActionButtonRow** — the one primary/secondary button-pairing convention: one solid primary action + one outline secondary action, left-to-right, same sizing/spacing on every card type:

```tsx
export function ActionButtonRow({
  primary,
  secondary,
}: { primary: ReactNode; secondary?: ReactNode }) {
  return (
    <div className={styles.row} data-testid="action-button-row">
      {primary}
      {secondary}
    </div>
  );
}
```
This is a layout-only wrapper — callers pass already-built Carbon `<Button kind="primary">`/`<Button kind="secondary">` (or `kind="danger"` for a red "Remove from package" primary per the screenshot's "solid red" treatment) as children; the wrapper only guarantees consistent flex layout/spacing/sizing, never dictates button content.
